### P01 · Deckline 产品说明手册
**标题**：Deckline 产品说明手册
**副标题**：这份手册讲什么、按什么顺序读？
**主张**：本手册共四部分：Deckline 是什么与适用范围、工作台与版本机制、风格与治理如何复用、安装与上手步骤。全篇 10 页，约 3–5 分钟读完；需要细节时按页内指向的 README 与 docs 查证。
**正文**：Deckline 是 DSH 上的 image deck 工作台：用对话改稿、一次出一页图、源文件只读——不是又一个 PPT 编辑器。
**提示词**：封面页（16:9，单页只承载一件事：这是 Deckline）。版式：居左起排，两行超大标题——第一行「Deckline」，第二行「deck 的生产线」，第二行字号略小一级；标题下方一行副标题「讲给谁 · 讲什么 · 怎么出图」。标题右下方放一张圆角面板，面板内竖排三条要点，每条一行短标题加一个细线图标：① 用对话改稿 ② 一次出一页图 ③ 源文件只读；三条等距、不堆字。右下角一行极小字注「IMAGE DECK STUDIO · DSH PLUGIN · v0.1」。整体左重右轻，左侧大面积留白。禁止：人物与照片、真实品牌 logo、英文营销口号、假数字、3D 球体。

### P02 · 做 deck 为什么总返工
**标题**：做 deck 为什么总返工
**副标题**：为什么改到第三版，还是说不清哪版被确认过？
**主张**：因为材料散在四个地方：想法在聊天里、稿子在文档里、图在另一个工具里、版本说不清——返工不是水平问题，是结构问题。
**正文**：因为材料散在四个地方：想法在聊天里、稿子在文档里、图在另一个工具里、版本说不清——返工不是水平问题，是结构问题。
**提示词**：信息页（16:9，一页讲清一个因果）。版式：顶部居左一行白色大字标题「做 deck 为什么总返工」，紧随一行 70% 灰度副标题「改到第三版，还是说不清哪版被确认过？」。中部主视觉是四块大小一致、间距相等的圆角面板横向并排（窄屏可 2×2），每块内只有三样东西：一个细线图标、一个中文短标题（≤6 字：想法在聊天里 / 稿子在文档里 / 图在另一个工具里 / 版本说不清）、一行 8–12 字说明；四块用极细的金色线段从底部收拢，汇到底部一块横跨全宽的窄条结论面板，条内一行字：「返工不是水平问题，是结构问题」。层级：标题 > 四面板 > 结论条，字号依次递减，全页中文不超过 40 字。背景材质、极光走向、玻璃与金色细线均由关联风格 GRD 提供，本页不另设配色。禁止：密集小字、卡通涂鸦、便签便条、照片、英文 slogan、虚构数字与署名。

### P03 · 一条产线，不是编辑器
**标题**：一条产线，不是编辑器
**副标题**：那 Deckline 到底解决哪一段？
**主张**：Deckline 是 DSH 的 image deck 工作台：从意图、脚本到出图、版本、治理都在一个工作区；一期只做整页图片 deck。
**正文**：Deckline 是 DSH 的 image deck 工作台插件：把意图、逐页脚本、出图、版本与治理文档放在同一工作区内。一期支持整页图片 deck（一页一张整页图），支持逐页修改与版本回退；出图默认一次一页，也可在对话里要求整批出、由 Agent 逐页执行。一期不支持 HTML deck 渲染、PPT 原生图层编辑、写回客户源目录与多人实时协作。
**提示词**：中央一行三段流程：「讨论 → 出图 → 留档」，三个节点各一个细线图标，下方各一行 6 字注释（讲给谁 / 怎么出图 / 有出处）；上下大量留白；底部一行小字「一期只做整页图片 deck」。

### P04 · 工作台三栏与分工
**标题**：工作台三栏与分工
**副标题**：三栏分别做什么、数据从哪来？
**主张**：工作台一屏三栏：Chat 讨论与确认、工作区出图与版本、资料库查证素材，三栏共用同一份 deck 数据。
**正文**：工作台一屏分三栏，从左到右依次是：① Chat——与 Agent 讨论、接收提案、逐条确认，所有改动都在这里发起；② 工作区——显示整页图、逐页画面要求与历史版本，出图与回退在此完成；③ 资料库——列出受控源文件、风格样张与事件记录，用于查证事实与取用素材。顶部标签用于切换意图、脚本、Design、修改日志、反馈、调研、支撑材料与治理文档。三栏共用同一份 deck 数据，因此不需要在工具之间复制粘贴。
**提示词**：三栏布局：左窄栏列 3 条对话摘要，中栏一张 16:9 整页缩略图（右下角页码 01），右窄栏列 3 条资料条目；三栏之间用极细分隔线；顶部一行标题。

### P05 · 版本机制：提案、确认、新版本
**标题**：版本机制：提案、确认、新版本
**副标题**：一次修改会经过哪几步？
**主张**：所有改动先提案、确认后落新版本——旧版保留可回退，出图一次一页、每页各自成版本。
**正文**：一次修改分四步：① 提案——Agent 生成改动并展示 diff，此时文件不变；② 确认——你逐条确认或整批确认；③ 落版——写成副本形式的新版本，旧版保留、不被覆盖；④ 归档——每页 prompt、出图结果、QA 记录与事件写入该版本。出图默认按页进行；在对话里要求整批出图时，Agent 仍逐页生成，每页各自成版本。版本号自 v001 递增，出图失败不产生新版本。
**提示词**：五步横向流程：提案 / 确认 / 落版本 / 单页出图 / 留档，每步一个编号 + 一行标签，第二步「确认」加一圈强调标记；链上方一行小字写版本号从 001 进到 002；留白大。

### P06 · 风格（design）与复用
**标题**：风格（design）与复用
**副标题**：风格怎么定义、怎么换、换完影响什么？
**主张**：风格是独立资产：一段画面描述 + 若干样张，关联到 deck 后出图自动带上，换风格不影响页面内容。
**正文**：风格（design）与 deck 是两种实体。风格由一段画面描述（styleBrief）与若干样张组成，有独立画布；deck 关联风格后，出图自动带上该风格提示词。使用方法：① 在 Designs 里选 8 个预设之一（各附基线样张），或自建风格并补样张；② 在 deck 上关联该风格；③ 逐页出图，需要换风格时重新关联即可。换风格只改变出图使用的画面语言，不改页面内容，也不覆盖已有版本。
**提示词**：2 行 4 列共 8 张小卡片：每张一个风格名（商务 / 深色 / 纸感 / 杂志 / 蓝图 / 白板 / 极简 / 渐变）+ 一条色块条；右下角一张虚线边框卡片写「＋ 自己的样张」；卡片间距均匀、整体留白。

### P07 · 治理文档与交接包
**标题**：治理文档与交接包
**副标题**：一份 deck 还包含哪些文档？
**主张**：治理文档 + 交接包让 deck 能换人接手：缺项与评分可见，交付前补齐即可。
**正文**：一份 deck 不只是几张图：意图、脚本、Design、修改日志、反馈、调研、支撑材料都在同一个工作区里，外加审稿与事实核对，缺哪份、治理分多少一眼看得见。交接包把脚本、每页 prompt、每页图、文档和事件一起打包——换人接手照文档就能往下改。你现在看的这份示例，就是这么攒出来的。
**提示词**：中央环形图分 8 段，每段内一行文档名（极简）；已齐的段内一个勾标，待补的段内一个圆点；右下角一个小方框写「交接包」，露出三张纸条；环形偏左，右侧留白。

### P08 · 安装与配置
**标题**：安装与配置
**副标题**：如何安装、key 放在哪里？
**主张**：安装三步：建 profile、装插件、启动；出图 key 只从环境变量或本机文件读，不落仓库。
**正文**：三条命令：建一个 deckline profile → 装插件 → 启动看工作台。出图 key 只从环境变量或本机 key 文件读，界面只显示「配没配」、不显示内容。没有 key 也能用 fake 模式把整条流程先跑一遍，不用先去申请什么。详细步骤在 README 与 docs/install.md。
**提示词**：左侧一个圆角终端窗口，窗内三行命令 + 一个方块光标；右侧一条钥匙图形上打叉，旁边两行短说明；整体居中偏左，留白大。

### P09 · 支持范围与不支持的功能
**标题**：支持范围与不支持的功能
**副标题**：一期支持什么、不支持什么？
**主张**：一期只做整页图片 deck：支持逐页改、版本回退、风格复用与交接导出；HTML deck 等暂不做。
**正文**：一期只做 image deck：一页一张整页图。出图一次一页，没有「一键出整套」的按钮——因为一次一页，每页的 prompt、QA 和版本才追得清。客户源目录只读，编辑产物落在本地工作区。HTML deck、PPT 原生图层编辑、多人实时协作暂不做。
**提示词**：左右两栏对照：左栏标题「能」+ 四条勾选清单，右栏标题「不」+ 四条叉号清单；中间一条极细竖线；底部一行小字「出图一次一页」。

### P10 · 上手步骤
**标题**：上手步骤
**副标题**：第一次使用按什么顺序做？
**主张**：上手三步：新建 deck 写清听众与时长 → 定意图与逐页脚本 → 逐页出图、不满意回退上一版。
**正文**：第 1 步：按 README 装好、打开工作台，新建一份 Deck，写清讲给谁、讲多久。第 2 步：和 Agent 把意图与逐页脚本聊定，每次改动都会先给你看 diff。第 3 步：一页一页出图，不满意就回退到上一版。想先看效果，可以直接打开仓库里的 samples/deckline-intro——也就是你现在看的这份。
**提示词**：左侧竖向三步 01 / 02 / 03，每步一行短句；右侧两张小卡片，一张写「README · docs/sample-deck.md」，一张写「MIT」；右下角两三笔方向箭头；留白大。
